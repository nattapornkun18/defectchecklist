# Defect Checklist — 10 · Deluxe King · Right

ฟอร์มตรวจ defect แบบเว็บ ใช้แทนการปริ้นเอกสารสีทุกครั้งที่ตรวจห้อง
เปิดบนมือถือ → เลือกหมวด → ดูรูปที่มีหมายเลขจุดตรวจ → กดผล → บันทึกลง Google Sheet

ถอดเนื้อหามาจากฟอร์มต้นฉบับครบทั้งหมด **488 จุดตรวจ ใน 10 หมวด**
พร้อมรูปถ่ายอ้างอิงที่มีหมายเลขกำกับของทุกหมวด

| # | หมวด | จุดตรวจ | # | หมวด | จุดตรวจ |
|---|---|---:|---|---|---:|
| 1 | ประตูทางเข้า (Door) | 72 | 6 | มินิบาร์ / ทีวี (Minibar) | 54 |
| 2 | อ่างล้างหน้า (Sink) | 49 | 7 | ห้องอาบน้ำ (Shower) | 78 |
| 3 | ที่วางกระเป๋า (Luggage) | 36 | 8 | ห้องน้ำ / สุขภัณฑ์ (Toilet) | 68 |
| 4 | เตียง (Bed) | 66 | 9 | ฝ้าเพดาน (Ceiling) | 16 |
| 5 | กระจก / หน้าต่าง (Mirror) | 47 | 10 | พื้น (Floor) | 2 |

> 📋 **จะสั่งงานรอบต่อไป** (เพิ่ม room type / ทำให้โรงแรมอื่น) — prompt สำเร็จรูปอยู่ที่ [`PROMPT.md`](PROMPT.md)

## ใช้งานยังไง (สำหรับผู้ตรวจ)

1. เปิดลิงก์เว็บบนมือถือ แล้ว **Add to Home Screen** ไว้ จะเปิดได้เหมือนแอป
2. เลือก **ห้อง / รอบตรวจ / ชื่อผู้ตรวจ** ที่หน้าแรก (ระบบจำชื่อผู้ตรวจไว้ให้)
3. แตะการ์ดหมวดที่จะตรวจ → เข้าหน้าหมวดนั้น
4. **แตะที่รูปเพื่อขยายเต็มจอ** ซูมด้วยสองนิ้ว หาหมายเลขจุดที่จะตรวจ
5. พิมพ์เลขนั้นในช่อง **"ดูเลขบนรูป แล้วพิมพ์เลขข้อที่นี่"** → กด **ไป** จะเลื่อนไปที่ข้อนั้นทันที
6. กดผลของข้อนั้น — **✓ ผ่าน / ↩ ส่งคืน / 🔧 แก้เอง** (กดซ้ำที่ปุ่มเดิม = ยกเลิกคำตอบ)
   - ถ้าเป็น **ส่งคืน** หรือ **แก้เอง** จะมีช่อง **จำนวนจุดที่พบ**, **รายละเอียด** และ **ถ่ายรูปแนบ** (สูงสุด 3 รูป/ข้อ) โผล่ขึ้นมา
7. ปุ่ม **✓✓** มุมขวาบน = ตั้งข้อที่ยังไม่ได้ตอบในหมวดนั้นเป็น "ผ่าน" ทั้งหมด (ใช้ตอนหมวดนั้นไม่มีปัญหา)
8. กลับหน้าแรก ทำหมวดถัดไปจนครบ แล้วกด **บันทึก**

### กรอกเฉพาะจุดที่มีปัญหา — ที่เหลือเป็น "ผ่าน" อัตโนมัติ

ไม่ต้องกด "ผ่าน" ทีละข้อทั้ง 488 จุด ให้กรอกเฉพาะจุดที่เป็น **ส่งคืน** หรือ **แก้เอง** เท่านั้น
ตอนกด **บันทึก** ระบบจะถามยืนยันครั้งเดียว แล้วตั้งจุดที่ไม่ได้กรอกทั้งหมดเป็น **ผ่าน** ให้เอง

แถบล่างจะบอกตลอดว่าเหลืออีกกี่จุดที่จะถูกนับเป็นผ่าน เช่น
*"ส่งคืน 2 · แก้เอง 1 · อีก 485 จุดที่ไม่กรอก = ผ่าน"*

**ผลการตรวจตรงกับฟอร์มกระดาษเดิม** — `ส่งคืน` = ส่งกลับให้ผู้รับเหมาแก้ · `แก้เอง` = ทีมเราแก้เอง
ส่วน `ผ่าน` เพิ่มเข้ามาเพื่อให้รู้ว่าตรวจครบแล้วจริง (ในกระดาษคือช่องที่เว้นว่างไว้)

### ตัวช่วยในหน้าหมวด

- **ตัวกรอง** — ทั้งหมด / ยังไม่ตรวจ / ส่งคืน / แก้เอง / ผ่าน
  ใช้ "ยังไม่ตรวจ" ตอนใกล้จบเพื่อดูว่าเหลือข้อไหนบ้าง
- **แถบความคืบหน้า** แยกสี เขียว = ผ่าน · แดง = ส่งคืน · เหลือง = แก้เอง
- ถ้าตั้งพิกัดหมุดไว้แล้ว (ดูหัวข้อถัดไป) จะมี **หมุดกดได้บนรูป** และปุ่ม 📍 ข้างแต่ละข้อเพื่อดูตำแหน่ง

### จุดที่ควรรู้

- **ข้อมูลเซฟลงเครื่องอัตโนมัติทุกครั้งที่กด** ปิดเบราว์เซอร์ / แบตหมด แล้วเปิดใหม่ ข้อมูลยังอยู่
- **ตรวจแบบไม่มีเน็ตได้** ถ้ากดบันทึกตอนไม่มีสัญญาณ ระบบจะเก็บคิวไว้แล้วขึ้นแถบเหลืองเตือน พอกลับมามีเน็ตจะส่งเองหรือกด "ลองส่งอีกครั้ง"
- **บันทึกซ้ำได้ ไม่เกิดแถวซ้ำ** — ระบบยึด ห้อง + วันที่ + รอบตรวจ เป็นคีย์ ส่งใหม่ = แทนที่ของเดิม
  (ถ้าเปลี่ยน 3 อย่างนี้ จะนับเป็นการตรวจครั้งใหม่)
- **แต่ละห้องแยกร่างกัน** สลับห้องไปมาได้โดยข้อมูลไม่ปนกัน
- **ปุ่ม 🖨** = พิมพ์หรือ Save as PDF สรุปผลตรวจทั้ง 488 ข้อ เผื่อต้องให้ผู้รับเหมาเซ็นรับ
- บันทึกลง Sheet เฉพาะข้อที่เป็น **ส่งคืน** และ **แก้เอง** — ข้อที่ผ่านนับรวมไว้ในแถวสรุปเท่านั้น เพื่อไม่ให้ Sheet บวม

## เปิดโหมด "แตะหมุดบนรูป" (ไม่บังคับ)

ตอนนี้รูปอ้างอิงเป็นรูปถ่ายที่มีหมายเลขพิมพ์อยู่บนรูปแล้ว ผู้ตรวจจึงดูเลขจากรูปแล้วพิมพ์เลขลงช่อง "ไป" ได้เลย
ถ้าอยากให้ **แตะที่หมุดบนรูปแล้วเด้งไปที่ข้อนั้นเลย** ต้องบอกระบบก่อนว่าหมายเลขแต่ละอันอยู่พิกัดไหนของรูป
ทำครั้งเดียวจบ ใช้ได้ตลอด:

1. เปิด **`tag.html`** (ลิงก์เดียวกับหน้าฟอร์ม แต่เปลี่ยน `index.html` เป็น `tag.html`)
2. เลือกหมวด → ระบบจะบอกว่า *"แตะที่หมายเลข 1"* → แตะบนรูปตรงกลางหมุดเลข 1
3. ทำไปเรื่อย ๆ ระบบเลื่อนไปข้อถัดไปให้เอง
   - **↩ ย้อนกลับ 1 จุด** ถ้าแตะพลาด
   - **ข้ามจุดนี้ →** ถ้าหมุดนั้นหาไม่เจอบนรูป
   - ความคืบหน้าเซฟอัตโนมัติ ทำค้างไว้แล้วกลับมาทำต่อได้
4. เสร็จแล้วกด **📋 คัดลอกโค้ด** แล้วเอาไปวางทับบรรทัด `pins: [],` ของหมวดนั้นใน `js/checklist.js`

> ระหว่างที่ยังไม่ได้วางโค้ดลง `checklist.js` หมุดจะขึ้นเฉพาะบนเครื่องที่ทำ tag ไว้
> พอ commit `checklist.js` แล้ว ทุกเครื่องจะเห็นหมุดเหมือนกัน

## ติดตั้งครั้งแรก (ทำครั้งเดียว)

### 1) เตรียม Google Sheet + Apps Script

1. เปิด Google Sheet ที่จะใช้เก็บข้อมูล (สร้างใหม่หรือใช้ไฟล์เดิมก็ได้)
2. เมนู **Extensions → Apps Script**
3. ลบโค้ดใน `Code.gs` เดิมทิ้ง แล้ววางเนื้อหาจาก [`apps-script/Code.gs`](apps-script/Code.gs) ทั้งหมด → 💾 Save
4. **Deploy → New deployment**
   - ฟันเฟือง ⚙ ข้าง "Select type" → **Web app**
   - **Execute as:** `Me`
   - **Who has access:** `Anyone` ← สำคัญ ถ้าเลือก "Anyone with Google account" หน้าเว็บจะส่งข้อมูลไม่ได้
   - **Deploy** → **Authorize access** → เลือกบัญชี → "Advanced" → "Go to (ชื่อโปรเจกต์) (unsafe)" → **Allow**
     (ที่ขึ้นเตือนเพราะเป็นสคริปต์ที่เราเขียนเอง ยังไม่ผ่านการรับรองจาก Google — ปกติ)
5. คัดลอก **Web app URL** (ลงท้ายด้วย `/exec`) เก็บไว้

> ระบบสร้างชีท `Inspections` และ `DefectLog` ให้อัตโนมัติตอนบันทึกครั้งแรก
> ถ้าอยากสร้างล่วงหน้า เลือกฟังก์ชัน `setupSheets` ใน Apps Script แล้วกด Run

หลังวางโค้ดแล้วรีเฟรชหน้าชีท จะมีเมนู **Defect Checklist** โผล่บนแถบเมนู
รวมคำสั่งดูแลระบบไว้ทั้งหมด — อธิบายแต่ละอันไว้ที่ [`docs/apps-script-menu.md`](docs/apps-script-menu.md)

### 2) เอาหน้าเว็บขึ้นออนไลน์

ง่ายที่สุดคือ **GitHub Pages** (ฟรี ไม่ต้องมีเซิร์ฟเวอร์):

1. ใน repo นี้ → **Settings → Pages**
2. **Source:** `Deploy from a branch`
3. **Branch:** เลือก branch ที่มีโค้ดนี้ + โฟลเดอร์ `/ (root)` → **Save**
4. รอ 1–2 นาที จะได้ลิงก์แบบ `https://nattapornkun18.github.io/defectchecklist/`

*(หรือลากทั้งโฟลเดอร์ไปวางบน Netlify Drop ก็ได้ ไม่ต้องตั้งค่าอะไรเลย)*

### 3) ใส่ Web App URL ลงในโค้ด (ทำครั้งเดียว ใช้กับทุกเครื่อง)

เปิด **[`js/config.js`](js/config.js)** แล้วแก้บรรทัดเดียว:

```js
const API_URL = 'https://script.google.com/macros/s/AKfyc.../exec';
```

commit + push → **จบ ผู้ตรวจทุกคนเปิดลิงก์แล้วใช้ได้ทันที ไม่ต้องกรอกอะไรเลย**
ไม่ต้องเข้าเมนู ⚙ ไม่ต้องวาง URL ซ้ำในมือถือแต่ละเครื่อง ล้างข้อมูลเบราว์เซอร์แล้วก็ยังใช้ได้เหมือนเดิม

> **สำคัญ** เวลาแก้ `Code.gs` ให้ Deploy แบบ **Manage deployments → ✏️ → Version: New version → Deploy**
> วิธีนี้ URL จะไม่เปลี่ยน ไม่ต้องมาแก้ `config.js` ซ้ำ
> (ถ้ากด **New deployment** ใหม่ทั้งอัน URL จะเปลี่ยน ต้องเอา URL ใหม่มาใส่ `config.js` ด้วย)

เมนู **⚙** ยังมีอยู่ แต่ใช้เฉพาะกรณีพิเศษ เช่นอยากให้มือถือเครื่องนั้นเครื่องเดียวส่งไป Sheet คนละไฟล์
ถ้าเผลอตั้งทับไว้ ระบบจะขึ้นเตือน ⚠️ พร้อมปุ่ม **คืนค่าเริ่มต้น** ให้กดกลับมาใช้ค่ากลางได้

## ข้อมูลที่บันทึกลง Sheet

### ชีท `Inspections` — สรุป 1 แถวต่อการตรวจ 1 ครั้ง

`Timestamp` · `InspectionID` · `Room` · `RoomType` · `Round` · `Inspector` · `Date` ·
`จุดตรวจทั้งหมด` · `ตรวจแล้ว` · `ผ่าน` · `ส่งคืน` · `แก้เอง` · `จำนวนจุดที่พบ` · `Progress %` · `หมายเหตุ`

### ชีท `DefectLog` — 1 แถวต่อ 1 จุดที่ติด ส่งคืน / แก้เอง

`Timestamp` · `InspectionID` · `Room` · `Round` · `Inspector` · `Date` ·
`หมวดที่` · `หมวด` · `หมวด (TH)` · `ข้อที่` · `จุดตรวจสอบ` ·
`ผล` · `จำนวน` · `รายละเอียด` · `รูปถ่าย`

หน้าเว็บอ่านสองชีทนี้กลับได้ด้วย (ปุ่ม ⭳ และหน้าสรุป) จึงไม่ควรลบ/สลับคอลัมน์
ถ้าต้องเพิ่มคอลัมน์ ให้เพิ่มต่อท้ายเพื่อไม่ให้ลำดับเดิมเลื่อน

### ชีท `สรุปรวม` — ตารางสรุปที่สร้างให้อัตโนมัติ

สร้างใหม่ทั้งแผ่นทุกครั้งที่มีการบันทึกจากหน้าเว็บ จัดหน้าเหมือนที่เคยทำมือ:
แยกกลุ่มตาม room type · แถว = ห้อง · คอลัมน์ = หมวด · มี `%`, `รวม` และแถว `รวมทั้งกลุ่ม`
ช่องยิ่งเข้ม = พบเยอะ (ไล่เฉดสีเดียว ตัวเลขอยู่ในช่องเสมอ)

ถ้าอยากสั่งอัปเดตเอง ในชีทจะมีเมนู **Defect Checklist → อัปเดตชีทสรุปรวม**
(เมนูจะโผล่หลังรีเฟรชหน้าชีท 1 ครั้ง)

> ชีทนี้ถูกเขียนทับทั้งแผ่นทุกครั้ง **อย่าพิมพ์อะไรเพิ่มลงไป** จะหาย
> ถ้าอยากคำนวณต่อ ให้อ้างอิงจาก `Inspections` / `DefectLog` แทน

หน้าเว็บจะบอก Apps Script เองว่า room type นี้มีหมวดอะไรบ้าง (ครั้งเดียวต่อเวอร์ชัน ตอนเปิดหน้า)
ตารางสรุปจึงมีคอลัมน์ครบทุกหมวด แม้บางหมวดจะไม่เคยเจอ defect เลย
ถ้าคอลัมน์ยังไม่ครบ ให้เปิดหน้าฟอร์มขณะมีเน็ต 1 ครั้ง แล้วสั่ง **อัปเดตชีทสรุปรวม** จากเมนู

**ถ้าแท็บ "สรุปรวม" ไม่โผล่:**
1. ชีทสร้างตอน **กดบันทึกจากหน้าเว็บ** เท่านั้น — deploy เฉย ๆ ยังไม่พอ ต้องกดบันทึก 1 ครั้ง
2. สั่งสร้างเองได้จากเมนู **Defect Checklist → อัปเดตชีทสรุปรวม**
   (เมนูโผล่หลังรีเฟรชหน้าชีท 1 ครั้ง)
3. อยากรู้ว่าพังเพราะอะไร → เมนู **Defect Checklist → ดูข้อผิดพลาดล่าสุดของชีทสรุป**
   หรือใน Apps Script เลือกฟังก์ชัน `buildSummarySheet` แล้วกด **Run** จะเห็น error ตรง ๆ

รูปถ่ายอัปโหลดเข้าโฟลเดอร์ Google Drive ชื่อ **Defect Checklist Photos**
แล้วใส่ลิงก์ในคอลัมน์ `รูปถ่าย` (ตั้งเป็น "ใครมีลิงก์ก็ดูได้" อัตโนมัติ)

จากสองชีทนี้ทำ Pivot Table ต่อได้เลย เช่น นับ defect ต่อห้อง / ต่อหมวด / ต่อผู้รับเหมา
หรือดูว่าจุดตรวจข้อไหนพังบ่อยที่สุดในทุกห้อง

## รหัสเข้าใช้งาน (ไม่บังคับ)

เปิดใช้ได้ถ้าอยากให้เฉพาะคนที่รู้รหัสถึงจะเข้าได้ มี 2 ระดับ:

| ระดับ | ทำอะไรได้ | ทำไม่ได้ |
|---|---|---|
| **ผู้ตรวจ** (inspector) | กรอกผลตรวจ · บันทึกลง Sheet · แนบรูป | ดูหน้าสรุป · ดึงข้อมูลกลับ |
| **ผู้ดูแล** (admin) | ทุกอย่าง | — |

**รหัสไม่ได้อยู่ในโค้ดหน้าเว็บ** แต่เก็บที่ Apps Script — หน้าเว็บส่งรหัสไปให้ตรวจทุกครั้ง
ใส่รหัสผิดจะไม่ได้ข้อมูลอะไรกลับมาเลย ต่อให้เปิด DevTools ก็ไม่เจอรหัส

> **"ใส่รหัสในหน้าเว็บ" ≠ "ตั้งรหัส"**
> หน้าเว็บทำได้แค่ *ตรวจ* ว่ารหัสที่พิมพ์ตรงกับที่เก็บไว้หรือไม่ — เป็นการเข้าใช้งาน ไม่ใช่การตั้ง
> การตั้งรหัสทำได้ที่เดียวคือ **เมนูในชีท** เท่านั้น
> เช็คสถานะได้จากเมนู **🔍 ตรวจสอบระบบ (diagnose)** จะมีบรรทัด 🔒 / 🔓 บอกว่าตั้งรหัสไว้แล้วหรือยัง

### วิธีเปิดใช้

1. ในชีท → เมนู **Defect Checklist → 🔑 ตั้งรหัสเข้าใช้งาน**
   กรอกรหัสผู้ดูแล แล้วรหัสผู้ตรวจ (ต้องไม่ซ้ำกัน)
2. แก้ [`js/config.js`](js/config.js) → `const REQUIRE_PIN = true;`
   (ถ้ารหัสยาวไม่ใช่ 4 หลัก แก้ `PIN_LENGTH` ด้วย)
3. บวก `ASSET_VERSION` + `version.json` + `?v=` ใน 3 ไฟล์ HTML ตามปกติ
4. commit + push

> **ลำดับสำคัญ** — ต้องตั้งรหัสในชีท**ก่อน** เปิด `REQUIRE_PIN`
> ถ้าเปิดก่อนตั้ง หน้าจอจะขึ้นว่า *"ยังไม่ได้ตั้งรหัสในชีท"* พร้อมบอกวิธี ไม่ปล่อยผ่านเงียบ ๆ

### ถ้าหน้าใส่รหัสไม่ขึ้น แต่บันทึกไม่ได้

เกิดตอนที่ **เซิร์ฟเวอร์ตั้งรหัสแล้ว แต่มือถือยังโหลดไฟล์เก่าที่ยังไม่รู้ว่าต้องใส่รหัส**
ระบบจัดการให้เอง — พอกดบันทึกแล้วโดนปฏิเสธ **หน้าใส่รหัสจะเด้งขึ้นมาทันที**
พร้อมบอกเหตุผลจากเซิร์ฟเวอร์ ใส่รหัสแล้วกดบันทึกซ้ำได้เลย

ผลตรวจที่กรอกไว้ไม่หาย และไม่ถูกโยนเข้าคิว (เพราะส่งอีกกี่ครั้งก็ไม่ผ่านถ้าไม่มีรหัส)

### การใช้งานประจำวัน

- ใส่รหัสครั้งเดียวต่อเครื่อง ระบบจำไว้ให้ — **ออฟไลน์ก็เข้าได้** เพราะไม่ต้องเช็คซ้ำทุกครั้ง
  (แต่ตอนบันทึกจริง Apps Script ตรวจรหัสทุกครั้งอยู่ดี)
- ผู้ตรวจจะไม่เห็นปุ่ม ⭳ กับลิงก์หน้าสรุปเลย และถ้าเปิด `summary.html` ตรง ๆ จะโดนกั้น
- เปลี่ยนคน / เปลี่ยนระดับ: เมนู ⚙ → **ออกจากระบบ** แล้วใส่รหัสใหม่
  (ผลตรวจที่ค้างในเครื่องไม่หาย)
- **เปลี่ยนรหัส**: ตั้งใหม่จากเมนูในชีท คนที่ถือรหัสเก่าจะใช้บันทึกไม่ได้ทันที
- **เลิกใช้ระบบรหัส**: เมนู **ยกเลิกระบบรหัส** แล้วตั้ง `REQUIRE_PIN = false`

## อยากตรวจห้องเดิมใหม่ ต้องลบในชีทก่อนไหม

**ไม่ต้องลบครับ** เลือกเอาว่าจะให้เป็นแบบไหน:

| อยากได้ | ทำยังไง | ผลในชีท |
|---|---|---|
| **ตรวจใหม่ทับของเดิม** (ตรวจผิด/กรอกผิด) | เลือก ห้อง + วันที่ + รอบ ชุดเดิม แล้วกดบันทึก | แถวเก่าถูกแทนที่ ไม่มีแถวซ้ำ |
| **ตรวจรอบใหม่ เก็บของเก่าไว้ด้วย** | เปลี่ยน **รอบตรวจ** (เช่นครั้งที่ 1 → ครั้งที่ 2) หรือเปลี่ยนวันที่ | เพิ่มเป็นการตรวจอีกครั้ง เก็บทั้งคู่ |
| **ลบทิ้งจริง ๆ** (กดผิดห้อง / ข้อมูลทดลอง) | ในชีท คลิกแถวนั้น → เมนู **Defect Checklist → 🗑 ลบผลตรวจของแถวที่เลือก** | ลบออกจากทั้ง 2 ชีท แล้วอัปเดตสรุปให้เอง |

ปุ่ม **ล้าง** ในหน้าเว็บลบแค่ร่างในเครื่อง **ไม่แตะชีทเลย** (ไม่ได้ต่อเน็ตด้วยซ้ำ)

> อยากเริ่มตรวจห้องเดิมใหม่หมด: กด **ล้าง** เพื่อเคลียร์หน้าจอ แล้วเปลี่ยน **รอบตรวจ** ก่อนเริ่ม
> จะได้ไม่ทับผลรอบก่อน และเทียบกันได้ว่าแก้ไปแล้วดีขึ้นแค่ไหน

### ทำไมปุ่มล้างถึงไม่ลบในชีทด้วย

ตั้งใจออกแบบให้แยกกัน ด้วย 4 เหตุผล:

1. **ปุ่มล้างถูกกดบ่อย** ระหว่างตรวจ (เริ่มห้องใหม่ / กรอกผิด) การลบข้อมูลส่วนกลางไม่ควรอยู่ห่างแค่ปุ่มเดียวบนมือถือ
2. **ผู้ตรวจมีหลายคน** คนหนึ่งเคลียร์เครื่องตัวเอง ไม่ควรลบของที่ทีมส่งให้ผู้รับเหมาไปแล้ว
3. **หน้างานมักไม่มีสัญญาณ** ถ้าให้ล้างสองที่พร้อมกัน จะเจอสภาพลบเครื่องสำเร็จแต่ลบชีทไม่สำเร็จ ข้อมูลจะเพี้ยนกันสองฝั่ง
4. **ชีทคือหลักฐาน** ว่าแจ้งอะไรไปแล้วบ้าง ไม่ควรลบได้จากหน้างาน

ที่สำคัญคือ **ล้างผิดไม่เสียหาย** เพราะกด ⭳ ดึงกลับมาได้ทันที
ส่วนการลบจริงต้องเข้าไปทำในชีท ซึ่งเป็นที่ของคนดูแล ไม่ใช่ผู้ตรวจหน้างาน

### วิธีลบในชีท

**วิธีหลัก:** เปิดแท็บ `Inspections` → คลิกแถวที่จะลบ → เมนู **Defect Checklist → 🗑 ลบผลตรวจของแถวที่เลือก**

ระบบจะแสดงรายละเอียดให้ยืนยันก่อน เช่น
*"ห้อง 310 · ตรวจครั้งที่ 1 · 2026-07-28 · ผู้ตรวจ กี้ · พบ defect 23 จุด
จะลบออกจาก Inspections 1 แถว และ DefectLog 2 แถว"*

กดยืนยันแล้วลบครบทั้งสองชีท และสร้างชีทสรุปใหม่ให้อัตโนมัติ

> **อย่าลบแถวเองด้วยมือ** เพราะจะลบได้แค่ชีทเดียว อีกชีทจะเหลือข้อมูลค้าง ทำให้สรุปเพี้ยน
> ถ้าหาแถวไม่เจอ ใช้เมนู **ลบผลตรวจ (พิมพ์ InspectionID เอง)** แทนได้

## ดึงข้อมูลจากชีทกลับมา (two-way)

เดิมข้อมูลไหลทางเดียว (ฟอร์ม → ชีท) ตอนนี้ดึงกลับได้ด้วย

หน้าแรกมีปุ่ม **⭳ ดึงข้อมูลจาก Sheet** — กดแล้วระบบจะหาผลตรวจของ **ห้อง + วันที่ + รอบ** ที่เลือกอยู่
ถ้าไม่เจอ จะถามว่าเอาครั้งล่าสุดของห้องนั้นมาแทนไหม

ใช้ตอนไหน:
- **ตรวจต่อจากเครื่องอื่น** — คนแรกตรวจครึ่งหนึ่งบันทึกไว้ คนที่สองกดดึงมาทำต่อได้
- **เปลี่ยนเครื่อง / ล้างเบราว์เซอร์** — ข้อมูลไม่หาย ดึงกลับมาได้
- **แก้ตัวเลขในชีทโดยตรง** แล้วอยากให้ฟอร์มตรงกัน — กดดึงกลับ

> ⚠️ การดึงข้อมูล **ทับของในเครื่องทั้งชุด** ถ้ามีผลตรวจค้างอยู่ ระบบจะถามยืนยันก่อน
> รูปถ่ายไม่ถูกดึงกลับมา (อยู่บน Drive แล้ว) เพื่อไม่ให้กินพื้นที่ในเครื่อง

## หน้าสรุปรวม (`summary.html`)

เข้าได้จากปุ่ม **📊 หน้าสรุปรวม** ที่หน้าแรก ดึงข้อมูลสด ๆ จากชีททุกครั้งที่เปิด

**ตัวเลขรวมด้านบน** — ห้องที่ตรวจแล้ว · จุดที่พบ defect + % · เฉลี่ยต่อห้อง · หมวดที่พบมากสุด

**ตารางไล่ตาม room type** เหมือนที่ทำมือในชีทเดิม:
แถว = ห้อง · คอลัมน์ = 10 หมวด · มี `รวม`, `%`, แถว `รวมทั้งกลุ่ม`, วันที่ และผู้ตรวจ
ช่องยิ่งเข้ม = พบเยอะ (ไล่เฉดสีเดียว อ่อน→เข้ม ตัวเลขพิมพ์อยู่ในช่องเสมอ ไม่ได้สื่อด้วยสีเพียงอย่างเดียว)
เอาเมาส์ชี้ที่ช่องจะบอกว่าเป็น ส่งคืน กี่รายการ แก้เอง กี่รายการ

**ตัวกรอง** — รอบตรวจ · ช่วงวันที่ · นับจาก (ส่งคืน+แก้เอง / ส่งคืนอย่างเดียว / แก้เองอย่างเดียว)
ทุกโหมดนับเป็น "จำนวนจุดที่พบ" เหมือนกัน จึงบวกกันได้ตรง ๆ

**กดดูรายจุดได้** — นี่คือส่วนที่ตอบว่า "จุดไหนบ้างที่ต้องส่งแก้"
- แตะที่ **ช่องตัวเลขของหมวด** → เห็นเฉพาะจุดของหมวดนั้น
- แตะที่ **เลขห้อง** หรือช่อง **รวม** → เห็นทุกจุดของห้องนั้น จัดกลุ่มตามหมวด

ในกล่องจะบอก **เลขข้อ · ชื่อจุดตรวจ · ส่งคืน/แก้เอง · จำนวน · รายละเอียดที่ผู้ตรวจพิมพ์ไว้ · ลิงก์รูปถ่าย**
พร้อมสรุปท้ายกล่อง และปุ่มพิมพ์เป็นใบสั่งงานส่งผู้รับเหมาได้เลย
ตัวกรอง "นับจาก" มีผลกับกล่องนี้ด้วย เช่นเลือก "ส่งคืน อย่างเดียว" จะเห็นเฉพาะจุดที่ส่งคืน

ถ้าห้องเดียวกันมีหลายรอบหรือหลายวันในช่วงที่เลือก ตารางจะแสดง **ครั้งที่บันทึกล่าสุด**
ปุ่ม 🖨 พิมพ์หรือ Save as PDF ได้

> ถ้าหน้าสรุปขึ้น error ว่าไม่รู้จัก action แปลว่า Apps Script ยังเป็นเวอร์ชันเก่า —
> ต้อง **Deploy → Manage deployments → ✏️ → New version → Deploy** ก่อน

## เวลาแก้รูปหรือข้อความ ต้องบวกเลขเวอร์ชันด้วย

เบราว์เซอร์ของผู้ตรวจ cache รูปและไฟล์ js ไว้ ถ้าไม่บอกว่ามีของใหม่ จะยังเห็นของเก่าต่อไป
**ทุกครั้งที่แก้ไฟล์ใน `img/`, `css/`, `js/` ต้องบวกเลขเวอร์ชันให้ครบทุกที่**
รวมแล้วเกือบ 20 จุดใน 5 ไฟล์ แก้มือแล้วตกหล่นง่ายมาก จึงมีสคริปต์ทำให้:

```bash
node tools/bump.mjs --dry    # ดูก่อนว่าจะแก้อะไรบ้าง
node tools/bump.mjs          # บวก 1 จากเลขปัจจุบัน
node tools/bump.mjs 20       # ตั้งเลขเองก็ได้
```

สคริปต์แก้ให้ครบทั้ง `js/config.js`, `version.json` และ `?v=` ทุกอันใน
`index.html` / `tag.html` / `summary.html` แล้วตรวจซ้ำว่าไม่มีเลขเก่าตกค้าง

*(ถ้าไม่มี Node ก็แก้มือได้ — ค้นหา `?v=` ในไฟล์ HTML แล้วเปลี่ยนให้หมด
พร้อมแก้ `ASSET_VERSION` ใน `js/config.js` และตัวเลขใน `version.json` ให้ตรงกัน)*

### ผู้ใช้จะรู้เองว่ามีของใหม่

ทุกหน้าถาม `version.json` แบบไม่ผ่านแคชตอนเปิด ถ้าเลขไม่ตรงกับที่โหลดมา
จะขึ้นแถบ **"มีเวอร์ชันใหม่ (vX) — อัปเดตเลย"** ลอยขึ้นมาให้กด กดแล้วโหลดใหม่ทันที
ไม่ต้องไปสอนใครล้าง cache อีก

เหตุผลที่ต้องมี: `?v=` กันแคชได้แค่ css/js/รูป **แต่ตัวไฟล์ HTML เองยังถูกแคชได้**
ถ้า HTML เก่าถูกแคชไว้ มันจะไปเรียก `?v=` เลขเก่าทั้งชุด — `version.json` จึงเป็นตัวเดียวที่เชื่อถือได้

เช็คเวอร์ชันบนเครื่องได้ที่เมนู **⚙** บรรทัด *"เวอร์ชันไฟล์บนเครื่องนี้"*

## แก้ไขเนื้อหาฟอร์ม

ทุกอย่างอยู่ใน **[`js/checklist.js`](js/checklist.js) ไฟล์เดียว**

```js
const ROOM_TYPE = '10 - Deluxe King - Right';
const ROOMS = Array.from({ length: 18 }, (_, i) => String(i + 3) + '10');  // 310 … 2010
const ROUNDS = ['ตรวจครั้งที่ 1', ...];

const CATEGORIES = [
  {
    id: 'door',                       // ห้ามซ้ำ และห้ามแก้ถ้ามีข้อมูลค้างอยู่
    name: 'Door', th: 'ประตูทางเข้า',
    img: 'img/cat01.jpg', imgW: 1240, imgH: 1687,
    notes: ['...'],                   // หมายเหตุใต้รูป (ไม่บังคับ)
    pins: [],                         // พิกัดหมุด — ได้จาก tag.html
    items: [
      { no: 1, th: 'เส้นขอบไม้ vertical - 01' },
      // ...
    ],
  },
];
```

- **แก้ข้อความจุดตรวจ / เพิ่ม / ลบ:** แก้ในอาเรย์ `items` ได้เลย
  `no` ต้องตรงกับหมายเลขบนรูป ถ้าไม่ตรงผู้ตรวจจะหาจุดไม่เจอ
- **เปลี่ยนรายชื่อห้อง:** แก้ `ROOMS`
- **เปลี่ยนรูปอ้างอิง:** วางไฟล์ใหม่ทับใน `img/` โดยใช้ชื่อเดิม (`cat01.jpg` … `cat10.jpg`) **จบ ไม่ต้องแก้โค้ด**
  ระบบอ่านขนาดรูปจากไฟล์เอง (`imgW`/`imgH` ใน `checklist.js` เป็นแค่ค่าสำรอง)
- **ทำ room type อื่น** (Deluxe Left / Suite): ก๊อป repo นี้ เปลี่ยน `checklist.js` + รูปใน `img/`
  แล้ว deploy เป็นอีกลิงก์ ชี้ Web App URL เดิมได้เลย เพราะคอลัมน์ `RoomType` แยกให้อยู่แล้ว

> ⚠️ ถ้าแก้ `id` ของหมวด ร่างที่ผู้ตรวจค้างอยู่ในเครื่องจะอ่านไม่เจอ
> ควรแก้ตอนที่ไม่มีใครค้างการตรวจอยู่ (ข้อมูลที่บันทึกลง Sheet แล้วไม่กระทบ)

## เรื่องความปลอดภัยที่ควรรู้

`API_URL` ใน `config.js` ถูกส่งไปที่เบราว์เซอร์ของผู้ใช้ ถ้า repo และ GitHub Pages เป็น public
**ใครก็ตามที่เปิดหน้าเว็บจะเห็น URL นี้ได้** และยิงข้อมูลเข้ามาที่ Sheet ได้ — เป็นข้อจำกัดของการ Deploy
แบบ "Who has access: Anyone" ซึ่งจำเป็นสำหรับให้หน้าเว็บส่งข้อมูลได้ ไม่มีวิธีซ่อนที่ได้ผลจริง
(ใส่ token ในโค้ดฝั่งเบราว์เซอร์ก็ยังอ่านเจออยู่ดี)

ความเสี่ยงจริงจำกัดอยู่แค่ **มีคนเขียนแถวขยะเข้ามาใน Sheet** เพราะสคริปต์ทำได้แค่เพิ่ม/แทนที่แถว
`doGet` ไม่คืนข้อมูลการตรวจออกไป (คืนแค่ชื่อไฟล์) จึงอ่านข้อมูลเก่าออกไปไม่ได้

ถ้ารับความเสี่ยงนี้ไม่ได้ ทางเลือกคือ **ตั้ง repo เป็น private แล้วโฮสต์หน้าเว็บในที่ที่ต้องล็อกอินก่อน**
(เช่น Google Sites ภายในองค์กร หรือ intranet ของโรงแรม) แทนการใช้ GitHub Pages แบบ public

## เรื่องสีของรูปอ้างอิง

รูป 9 จาก 10 หมวดใช้ไฟล์ที่ export แยกรายหมวดมา **สีถูกต้อง** แล้ว
เหลือ **Floor (`cat10.jpg`)** หมวดเดียวที่ยังใช้รูปจาก PDF รวม ซึ่งสีเพี้ยน

สาเหตุที่ PDF รวมทำสีเพี้ยน — ตรวจแล้วว่าไม่ใช่ปัญหาตอนถอดไฟล์:
- JPEG ที่ฝังใน PDF เป็น YCbCr 3 แชนเนลปกติ ไม่มี ICC profile ไม่มี CMYK
- content stream ของ PDF มีแต่สี **ดำ/ขาว/เทา** เท่านั้น — เส้นสีชมพูจึงไม่ใช่ vector แต่ถูกอบมาในรูปแล้ว
- วัดพิกเซลอิ่มสีในรูปที่ฝังมา: โทนชมพู/บานเย็น = **0.0%** ขณะที่ในรูปต้นฉบับเป็นสีหลักของภาพ

สรุปคือสีหายไปตอน Google Sheet export เป็น PDF กู้คืนจาก PDF ไม่ได้

**วิธีแก้:** export หมวดนั้นออกมาแยกไฟล์จากในชีท แล้ววางทับใน `img/` ใช้ชื่อเดิม
(ลำดับตามตารางหมวดด้านบนของไฟล์นี้) วางทับแล้วใช้ได้เลย ไม่ต้องแก้โค้ด

รูปถูกก๊อปเข้ามาโดยไม่บีบอัดซ้ำ เพราะทดลองแล้วการ re-encode ที่คุณภาพ 0.88
ทำให้ไฟล์ 217 KB เหลือ 25 KB ซึ่งทำลายความคมของตัวเลขกำกับจุดตรวจ

เนื้อหาถอดมาจาก PDF ที่ export จาก Google Sheet ต้นฉบับ ครบทั้ง 488 ข้อ

ชื่อหมวดที่ 3 ในชีทต้นฉบับเขียนว่า **"Language"** ซึ่งพิมพ์ผิดจาก **"Luggage"**
